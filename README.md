# Cell Painting DINO: Self-Supervised Morphological Profiling

A research project exploring whether **self-supervised learning** can discover biologically meaningful representations directly from Cell Painting microscopy images—without using compound identities or mechanism-of-action (MoA) labels during training.

This repository contains an end-to-end pipeline for training a modified **DINOv2 Vision Transformer** on 5-channel Cell Painting images from the **JUMP Cell Painting Consortium**, evaluating the learned embeddings, and deploying an interactive web application for exploring the resulting embedding space.

> **Status:** Research proof of concept. This project investigates whether self-supervised representation learning can recover pharmacologically meaningful structure from Cell Painting images. It is **not** a validated screening or drug discovery tool.

---

## Overview

Traditional morphological profiling often relies on hand-engineered features (e.g. CellProfiler) or supervised learning requiring extensive biological annotations. This project instead asks:

> **Can a vision model trained only on microscopy images learn representations that capture biologically meaningful similarities between compounds?**

To answer this question, the project implements an end-to-end workflow including:

- Data acquisition from the JUMP Cell Painting dataset
- Metadata construction and preprocessing
- Self-supervised DINO training
- Embedding extraction and post-processing
- Representation evaluation
- Interactive visualization through a Flask web application

---

## Features

- Modified **DINOv2 ViT-S/14** for 5-channel fluorescence microscopy
- Fully self-supervised training (no compound or MoA labels)

- End-to-end reproducible training pipeline

## Pipeline

The project follows the workflow below.

```
JUMP Cell Painting Images
            │
            ▼
 Metadata Construction
            │
            ▼
 Image Preprocessing
            │
            ▼
 Self-Supervised DINO Training
            │
            ▼
 Embedding Extraction
            │
            ▼
 Post-processing
            │
            ▼
 Evaluation
            │
            ▼
 Interactive Web Application
```

### 1. Data Acquisition

Images are downloaded from the **JUMP Cell Painting Consortium**, using a curated subset of compound perturbation plates. Metadata from multiple sources is merged to associate each image with compounds, wells, and mechanism-of-action annotations (used **only for evaluation**, never for training).

### 2. Image Preprocessing

Each 5-channel fluorescence image undergoes:

- Per-image percentile normalization
- DNA-based Otsu thresholding
- Foreground-aware crop generation
- Conversion into PyTorch training tensors

Optional offline tile precomputation accelerates training.

### 3. Self-Supervised Training

The model uses a modified **DINOv2 ViT-S/14** backbone adapted for five input channels.

Training follows the standard DINO framework:

- Student–teacher architecture
- Multi-crop learning
- EMA teacher updates
- Mixed precision training
- Cosine learning-rate scheduling
- Foreground-aware crop sampling

No biological labels are used during optimization.

---

## Model

### Architecture

- **Backbone:** DINOv2 ViT-S/14
- **Input:** Five Cell Painting fluorescence channels
- **Embedding size:** 384 dimensions
- **Representation:** CLS token

The RGB patch embedding is extended to five channels by initializing the additional channels from the mean of the pretrained RGB filters rather than random initialization.

### Post-processing

Before similarity comparisons, embeddings undergo:

1. Median Absolute Deviation (MAD) normalization
2. PCA sphering (whitening)
3. L2 normalization

These steps substantially improve cross-plate consistency and reduce technical batch effects.

---

## Evaluation

The primary evaluation asks whether wells corresponding to the same compound become more similar than random pairs, even when imaged on different plates.

Additional analyses include:

- Cross-plate replicate enrichment
- MoA neighborhood purity
- Compound retrieval
- Linear probe evaluation
- UMAP visualization
- Channel ablation
- Attention map analysis

## Results

The web app's currently deployed embeddings are from **epoch 150 of training run `071226_213002`**. The underlying dataset is a subset of the **JUMP Cell Painting Consortium** containing:

- **23 Cell Painting plates**
- **8,243 wells**
- **306 compounds**
- **211 mechanism-of-action labels**

Although MoA labels are included in the dataset, they are **never used during training**. They are used only to evaluate whether biologically similar compounds naturally cluster together in the learned embedding space.

### Summary

The learned representations demonstrate:

- Above-chance compound retrieval
- Improved replicate similarity after post-processing
- Modest MoA clustering
- Remaining plate/batch effects, even after correction

Overall, the model learns biologically meaningful structure, but the resulting embeddings should be interpreted as generating hypotheses rather than providing definitive biological conclusions.

## Cell Painting Embedding Explorer

The project includes an interactive Flask web application for exploring the learned embedding space.

Features include:

- Interactive 2D and 3D UMAP visualization
- Search by compound, well, or mechanism of action
- Nearest-neighbor similarity search
- Representative Cell Painting thumbnails
- Vision Transformer attention maps
- Per-channel importance visualization
- Guided onboarding tutorial

The application uses precomputed embeddings and metadata, allowing it to run without GPU acceleration.

## Running the Pipeline

A typical workflow is:

```bash
# Download data
python scripts/download_compound_plates.py

# Build metadata
sbatch datasets/build_metadata_table.slurm

# Preprocess images
sbatch datasets/preprocess.slurm

# Train DINO
sbatch models/dino/train_dino.slurm

# Extract embeddings
sbatch analysis/embed.slurm

# Build web app data (well/compound parquet + embeddings)
python scripts/prepare_phase1_data.py --emb embeddings/<run>/embeddings_epoch_N.npy
python scripts/prepare_phase2_compounds.py

# Generate the webapp's per-well visual assets from that same checkpoint/embeddings
sbatch scripts/generate_web_thumbnails.slurm --emb embeddings/<run>/embeddings_epoch_N.npy
sbatch scripts/generate_web_attention_maps.slurm --run_dir checkpoints/<run> --epoch N --emb embeddings/<run>/embeddings_epoch_N.npy
sbatch scripts/generate_web_channel_importance.slurm --run_dir checkpoints/<run> --epoch N --emb embeddings/<run>/embeddings_epoch_N.npy

# Launch the web application
cd webapp
python app.py
```

The three `generate_web_*` jobs must all be pointed at the *same* embeddings
as each other and as the `prepare_phase1_data.py` run above — each
independently picks a representative site per well from whatever embeddings
it's given, so mismatched inputs produce a thumbnail, attention overlay, and
channel-importance score that don't actually describe the same image.

Most stages can also be executed through the provided SLURM scripts for distributed execution on an HPC cluster.

## Deployment

The Flask application depends only on:

- `app_data/`
- `webapp/static/`

Large static assets (thumbnails and attention maps) are distributed separately as GitHub Release assets rather than being tracked in Git. Deployment consists of:

1. Generating the assets
2. Uploading them to a GitHub Release
3. Running `scripts/fetch_web_assets.py` during deployment

This keeps the repository lightweight while allowing the web application to remain fully self-contained after deployment.

---

## Limitations

This project is intended as a **research proof of concept**, not a production-ready drug discovery platform.

Current limitations include:

- Training performed on a relatively small subset of the JUMP Cell Painting dataset
- Residual plate and batch effects remain after post-processing
- MoA clustering is above chance but modest in absolute terms
- UMAP is intended for visualization only and should not be interpreted quantitatively
- Similarity relationships should be viewed as hypotheses requiring biological validation
